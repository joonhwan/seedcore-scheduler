## 1. ① 로그인 유지 — 확정 사양

### 회신 내용
로그인 후 12시간 유지, 만료 10분 전에 연장 팝업을 띄워 12시간을 다시 확보하는 방식(관공서 시스템 방식).

### 확정 사양

1. **세션 수명은 12시간 하나로 단순화합니다.** 지금은 "마지막 조작으로부터 30분"과 "로그인 후 12시간" 두 겹인데, 앞의 30분 규칙을 없애고 12시간만 남깁니다. 조작 여부와 무관하게 로그인 후 12시간이 기준선이 됩니다.
2. **1차 검토에서 확인한 쿠키 결함을 함께 고칩니다.** 브라우저 쿠키의 만료 시각도 12시간으로 맞춰 발급합니다. 이 수정이 없으면 아래 팝업이 뜨기도 전에 30분 만에 끊깁니다.
3. **만료 10분 전 연장 팝업**을 띄웁니다. 남은 시간을 초 단위로 세어 보여주고, 버튼은 두 개입니다.
   - "로그인 연장": 세션을 새로 발급해 다시 12시간을 확보합니다.
   - "지금 로그아웃": 즉시 종료합니다.
4. **팝업을 놓친 경우**에는 만료 시각에 자동 로그아웃되며, 다시 로그인하는 화면이 뜹니다. 이때 편집 중이던 내용이 있으면 그 사실을 함께 알려 저장을 놓치지 않게 합니다.
5. 화면 오른쪽 위에 **남은 시간**을 상시 표시해 언제 끊기는지 미리 알 수 있게 합니다.

### 함께 확인이 필요한 사항
연장 횟수에 제한을 둘지 결정이 필요합니다. 제한을 두지 않으면 화면을 계속 열어둔 채 무기한 사용할 수 있습니다. 폐쇄망이므로 제한을 두지 않는 편이 편리하다고 보아 **무제한 연장**을 기본안으로 잡았습니다. 다른 판단이 있으시면 알려주시기 바랍니다(2차 확인 ㉮).

### 데이터베이스 변경
없습니다. 기존 세션 테이블을 그대로 사용합니다.

## 2. ② 사용자 그룹(부서) 관리 — 신규 기능, 요구 확대

### 회신 내용
운영기술센터 21명, 구매팀 3명, 경영관리 10명처럼 인원을 그룹으로 묶어 관리하고, 프로젝트를 만들 때 그룹을 골라 일괄 참여시키며, 그룹 밖 인원(임원 등)은 개별로 덧붙이는 방식.

### 판정: 구현 가능하나 신규 기능입니다

당초 "전체 선택 버튼 추가"로 보았던 것이, 조직 구조를 시스템에 담는 기능으로 확대되었습니다. 현재 시스템에는 부서나 그룹 개념이 전혀 없습니다. 사용자는 아이디·이름·역할(ADMIN/USER)만 가지며, 소속을 나타내는 자리가 없습니다.

다만 **이 기능은 9번·10번(인원별 프로젝트 권한 관리)과 맞물려 관리 부담을 크게 덜어줍니다.** 그룹이 생기면 "구매팀 전원을 이 프로젝트에 넣는다", "운영기술센터 소속이 참여 중인 프로젝트를 본다" 같은 일이 한 번에 됩니다. 투자할 가치가 있다고 판단합니다.

### 확정 사양

**가. 그룹 관리 화면 (관리자 모드 신규)**
- 그룹 생성·이름 변경·삭제
- 그룹에 인원 추가·제외 (여러 명 한꺼번에 선택)
- 그룹별 인원수와 소속자 목록 조회

**나. 프로젝트 생성 화면 개편**
- 그룹 목록에서 참여 그룹을 고릅니다(복수 선택 가능). 고르면 그 그룹 소속 인원이 모두 참여자로 들어옵니다.
- 그룹 밖 인원은 지금처럼 검색해 개별로 덧붙입니다.
- 참여자마다 역할(MANAGER/MEMBER)을 지정합니다. **그룹으로 들어온 인원의 기본 역할은 MEMBER**로 두고, MANAGER는 개별로 지정하는 방식을 기본안으로 잡았습니다.
- 최종 참여자 명단을 한 화면에서 확인한 뒤 생성합니다.

**다. 기존 프로젝트에도 그룹 단위 추가**
- 이미 만든 프로젝트의 멤버 관리 화면에서도 그룹을 골라 일괄 추가할 수 있게 합니다.

### 중요한 설계 판단 — 그룹과 프로젝트의 관계

여기에 갈림길이 하나 있어 확인이 필요합니다(2차 확인 ㉯).

| 방식 | 동작 | 장점 | 단점 |
|---|---|---|---|
| **명단 복사 방식** | 프로젝트 생성 시점의 그룹 인원을 참여자로 복사. 이후 그룹에 사람이 들어오고 나가도 기존 프로젝트는 그대로 | 참여자가 예고 없이 바뀌지 않음. 이력 추적이 명확함 | 신입이 들어오면 진행 중인 프로젝트에 일일이 넣어야 함 |
| **연동 방식** | 그룹 자체를 프로젝트에 묶고, 그룹 인원이 바뀌면 참여자도 자동으로 따라 바뀜 | 인사 이동이 자동 반영됨 | 그룹에서 뺀 사람이 여러 프로젝트에서 한꺼번에 빠짐. 권한이 조용히 바뀌어 사고 위험 |

**명단 복사 방식을 권장드립니다.** 권한이 사람 모르게 바뀌는 것은 일정 관리 시스템에서 위험 요소이며, 신입이 들어왔을 때는 10번 기능(인원을 고르고 참여할 프로젝트를 여러 개 체크)으로 몇 번의 조작이면 해결되기 때문입니다.

### 데이터베이스 변경 (신규 테이블 2개)

```
user_groups          그룹 자체
  id, name(고유), description, created_at, updated_at

user_group_members   그룹 소속 (다대다)
  group_id, user_id, added_by, added_at
  기본키: (group_id, user_id)
```

한 사람이 여러 그룹에 속할 수 있는 구조로 잡았습니다(겸직·파견 대응). 1인 1소속으로 제한할지 여부도 확인이 필요합니다(2차 확인 ㉰).

## 3. ③ 간트 확대·축소와 출력 — 절반은 이미 있습니다

### 회신 내용
화면을 일정 배율로 확대·축소하고, **그 화면 그대로를 출력물로 내보내는** 기능. 4개월 프로젝트라면 월 단위 전체 출력, 4주 단위 출력, 1주 단위 날짜별 출력이 모두 필요.

### 먼저 알려드릴 사항 — 단위별 출력은 이미 됩니다

현재 프로젝트 화면의 **내보내기 메뉴에 이미 다음 기능이 들어 있습니다.**

| 기능 | 지원 내용 |
|---|---|
| 간트 이미지(PNG) 내보내기 | **일·주·월·분기** 중 단위 선택, 표시할 트리 단계 선택(예: 2단계까지만), 밝은/어두운 테마 선택 |
| 엑셀(.xlsx) 간트 내보내기 | **일·주·월** 중 단위 선택, 개요(윤곽선) 포함 여부 선택 |

즉 "월 단위 전체 진행 상황"과 "주 단위", "일 단위" 출력물은 지금도 뽑을 수 있습니다. 사용설명서에서 위치를 확인하실 수 있도록 별도로 안내드리겠습니다. 혹시 이 기능을 이미 써 보신 뒤에도 부족하다고 느끼신 것이라면 어떤 점이 부족했는지 알려주시면 그 부분을 고치겠습니다(2차 확인 ㉱).

### 현재 기능의 한계 — 여기가 실제로 부족한 부분

1. **기간을 잘라 뽑을 수 없습니다.** 지금은 프로젝트 전체 기간을 한 장에 담습니다. 4개월 프로젝트를 일 단위로 뽑으면 가로로 매우 긴 이미지 한 장이 나오고, 인쇄하면 글씨를 알아보기 어렵습니다. "3월 1일~3월 28일 구간만" 같은 지정이 불가능합니다.
2. **화면에서 확대한 배율이 출력에 반영되지 않습니다.** 화면 배율과 출력 배율이 따로 놀아, 화면에서 보기 좋게 맞춘 상태를 그대로 뽑을 수 없습니다.

### 확정 사양

**가. 화면 배율 (요청하신 10% 단위)**
- 확대·축소를 10% 단위로 바꾸고, 현재 배율을 숫자로 표시합니다.
- 잘게 나뉘면 버튼을 여러 번 눌러야 하므로 슬라이더를 함께 둡니다.
- 기존의 화면 맞춤 버튼과 키보드 단축키는 그대로 둡니다.

**나. 보고 있는 화면 그대로 내보내기**
- 내보내기 대화상자에 "지금 화면 그대로" 선택지를 추가해, 현재 배율과 펼침 상태를 그대로 출력물에 담습니다.

**다. 기간을 지정한 출력 (신규)**
- 출력 대상 기간을 직접 지정합니다(시작일~종료일).
- 자주 쓰는 범위는 버튼으로 제공합니다: 전체 기간 / 이번 달 / 이번 주 / 앞으로 4주.

**라. 여러 장으로 잘라 내보내기 (신규)**
- "4개월을 4주씩 잘라 4장", "한 달을 1주씩 잘라 5장"처럼 기간을 자동 분할해 여러 장을 한 번에 내려받습니다.
- 여러 파일이 되므로 압축 파일 하나로 묶어 내려받는 방식을 기본안으로 잡았습니다. 인쇄용 PDF 한 부(여러 쪽)로 묶는 방식도 가능하며, 어느 쪽이 편하신지 확인이 필요합니다(2차 확인 ㉲).

### 데이터베이스 변경
없습니다. 모두 화면 쪽 작업입니다.

## 5. ⑤ 서버 재시작 예고와 접속자 확인 — 확정

### 회신 내용
재시작 5분 전부터 팝업 알림, 사용자가 확인 버튼을 눌러 닫음, 1분 주기로 남은 시간을 다시 표시.

### 확정 사양

**가. 관리자 쪽**
- 재시작 예정 시각과 안내 문구를 등록합니다. 등록한 예고는 취소할 수 있습니다.
- **현재 접속자 목록**을 함께 보여줍니다. 이름, 마지막 활동 시각, 접속 IP가 나옵니다.

**나. 사용자 쪽**
- 재시작 5분 전부터 화면 위에 팝업이 뜹니다. 남은 시간이 초 단위로 줄어드는 것이 보입니다.
- "확인" 버튼으로 닫습니다.
- 닫은 뒤에도 1분마다 다시 떠서 남은 시간을 알립니다(5분 전, 4분 전, … 1분 전).
- 편집 중인 내용이 있으면 팝업에 "저장하지 않은 변경이 있습니다"를 함께 띄웁니다.

**다. 접속자 판단 기준**
회신에 기준 시간이 없어 **"최근 5분 이내에 활동한 사람"**을 기본안으로 잡았습니다. 브라우저를 그냥 닫은 사람은 최대 5분 동안 목록에 남습니다. 다른 기준을 원하시면 알려주시기 바랍니다(2차 확인 ㉳).

### 데이터베이스 변경 (신규 테이블 1개)

```
server_notices       재시작 예고 등 공지
  id, kind, message, scheduled_at, created_by, created_at, canceled_at
```

예고는 한 번에 하나만 유효하도록 다루되, 지난 예고 기록은 남겨 언제 재시작했는지 추적할 수 있게 합니다.

## 6. ⑥ 사용자 정리 — 확정 (두 방식 모두 구현)

### 가. 활동 기록이 없는 계정 완전 삭제
- 프로젝트 참여, 일정 생성·수정, 댓글, 변경 이력이 **모두 0건**인 계정에 한해 삭제 버튼이 나타납니다.
- 활동이 있는 계정에서는 버튼이 아예 보이지 않고, 그 이유를 함께 안내합니다("이 계정은 3개 프로젝트에 참여하고 일정 47건을 수정한 기록이 있어 삭제할 수 없습니다. 퇴사 처리를 이용하십시오").
- 삭제 전 확인 창을 거치며, 삭제 사실은 감사 기록에 남습니다.

### 나. 활동 기록이 있는 계정은 퇴사 처리
- 퇴사 처리하면 사용자 목록 기본 화면에서 사라집니다. "퇴사자 포함 보기"를 켜야 나타납니다.
- 로그인이 차단되고, 그 계정의 세션이 즉시 모두 끊깁니다.
- 프로젝트 참여자 선택 목록, 그룹 추가 대상 목록에서도 제외됩니다.
- 과거의 일정 이력과 댓글에는 이름이 그대로 남습니다.
- 되돌릴 수 있습니다(복직 처리).

### 데이터베이스 변경 (컬럼 1개 추가)

```
users 테이블에 retired_at (날짜, 비어 있을 수 있음) 추가
  - 값이 없으면 재직, 값이 있으면 그 시각에 퇴사 처리된 것
```

기존의 활성·비활성 구분은 그대로 둡니다. 비활성은 "일시적으로 접속을 막음", 퇴사는 "조직을 떠나 목록에서 감춤"으로 뜻이 다르기 때문입니다.

## 7. 데이터베이스 변경 총괄

`AGENTS.md` §7 규정에 따라 변경 내용을 미리 정리합니다.

| 변경 | 대상 | 내용 | 관련 항목 |
|---|---|---|---|
| 신규 테이블 | `user_groups` | 그룹 정보 | ② |
| 신규 테이블 | `user_group_members` | 그룹 소속(다대다) | ② |
| 신규 테이블 | `server_notices` | 재시작 예고 공지 | ⑤ |
| 컬럼 추가 | `users.retired_at` | 퇴사 처리 시각 | ⑥ |

- 모두 **기존 데이터를 손대지 않고 덧붙이는 변경**입니다. 기존 행이 지워지거나 형태가 바뀌지 않습니다.
- 새 컬럼은 비어 있는 상태로 추가되므로 기존 사용자는 모두 재직 상태로 유지됩니다.
- 반영 절차는 기존 마이그레이션 파이프라인을 그대로 따릅니다. 운영 서버는 재시작 시 마이그레이션이 적용되며, 적용 전 데이터베이스 백업을 먼저 수행하겠습니다.
- 다음 항목은 **데이터베이스 변경 없이** 처리됩니다: ① 로그인 유지, ③ 간트 배율·출력, ④ 수정일, 4번 목록 스크롤, 5-2번 통합 로그, 8번 접속자 목록, 9·10번 인원별 권한 관리.

## 8. 2차 확인 요청 문안

아래 내용은 사용자 대표께 그대로 전달하실 수 있도록 정리한 것입니다.

> 상세한 회신 감사합니다. 주신 내용을 모두 반영해 구현 사양을 확정했습니다. 확정 과정에서 몇 가지가 더 필요해 다시 여쭙습니다.
>
> 먼저 한 가지 알려드릴 것이 있습니다. **③에서 말씀하신 월 단위·주 단위·일 단위 출력물은 이미 시스템에 들어 있습니다.** 프로젝트 화면의 내보내기 메뉴에서 간트 이미지(PNG)나 엑셀로 내보낼 때 일·주·월·분기 중에서 고르실 수 있고, 표시할 트리 단계도 정할 수 있습니다. 사용 위치를 따로 안내드리겠습니다. 다만 **기간을 잘라서 뽑는 것**(예: 3월 1일~28일 구간만, 또는 4개월을 4주씩 잘라 네 장으로)은 지금 안 되므로 새로 만들겠습니다.
>
> **㉮ 로그인 연장 횟수** — 연장 팝업에서 "연장"을 누르면 12시간이 다시 확보됩니다. 이 연장에 횟수 제한을 둘까요? 제한하지 않으면 화면을 열어둔 채 며칠이고 쓸 수 있습니다. 폐쇄망이므로 제한 없이 두는 것을 기본안으로 잡았습니다.
>
> **㉯ 그룹 인원이 바뀔 때 기존 프로젝트 처리** — 구매팀에 신입이 들어와 그룹에 추가되었을 때, 그 사람이 이미 진행 중인 프로젝트에 (가) 자동으로 참여자가 되어야 하는지, (나) 관리자가 필요한 프로젝트에만 넣어주는 방식이 좋은지 알려주시기 바랍니다. (나)를 권장드립니다. (가)로 하면 그룹에서 사람을 뺄 때 여러 프로젝트에서 한꺼번에 권한이 사라져 사고 위험이 있습니다. (나)를 택하셔도 10번 기능으로 "이 사람을 이 프로젝트들에 넣기"를 몇 번의 조작으로 처리할 수 있습니다.
>
> **㉰ 한 사람이 여러 그룹에 속할 수 있는지** — 겸직이나 파견 인원을 두 그룹에 함께 넣을 수 있게 할지, 1인 1소속으로 제한할지 알려주시기 바랍니다. 여러 그룹 소속을 허용하는 쪽을 기본안으로 잡았습니다.
>
> **㉱ 기존 내보내기 기능의 사용 여부** — 위에 말씀드린 단위별 내보내기를 이미 써 보셨는지요? 써 보신 뒤에도 부족하다고 느끼셨다면 어떤 점이었는지 알려주시면 그 부분을 고치겠습니다.
>
> **㉲ 여러 장 출력물을 받는 형태** — 4개월을 4주씩 잘라 네 장을 뽑으면 파일이 여러 개가 됩니다. (가) 압축 파일 하나로 묶어 받기, (나) 인쇄용 PDF 한 부(네 쪽)로 받기 중 어느 쪽이 편하신지 알려주시기 바랍니다. 회의 자료로 인쇄하실 일이 많다면 (나)가 편합니다.
>
> **㉳ 접속자 판단 기준** — "최근 5분 이내에 활동한 사람"을 접속 중으로 보는 것을 기본안으로 잡았습니다. 브라우저를 그냥 닫은 분은 최대 5분간 목록에 남습니다. 다른 기준을 원하시면 알려주시기 바랍니다.
>
> 마지막으로 진행 순서를 말씀드립니다. **로그인이 끊기는 문제와 수정일이 갱신되지 않는 문제를 먼저 고쳐 빠르게 배포**하고, 그다음 화면 개선(목록 스크롤, 간트 배율, 전체 선택), 이어서 그룹 관리와 인원별 권한 관리, 마지막으로 재시작 예고와 통합 로그 순으로 진행하려 합니다. 순서에 조정이 필요하시면 알려주시기 바랍니다.

## 9. 개정된 진행 순서

| 단계 | 항목 | 확인 대기 | 데이터베이스 변경 |
|---|---|---|---|
