====================================================================
  📌 SAM Scheduler (Seedcore Scheduler) 사내 서버 관리자 가이드
====================================================================

1. 디렉터리 구성 안내
--------------------------------------------------------------------
  sp-server.exe         : 메인 웹 서버 (웹 UI + REST API + DB 통합 단일 실행 파일)
  sp-backup.exe         : 관리자 전용 DB 백업 및 특정 시점 복구 CLI 도구
  sp-reset-admin.exe    : 관리자(admin) 비밀번호 즉시 재설정 CLI 도구
  sp-migrate.exe        : DB 스키마 업그레이드 도구 (새 버전 배포 후 필요할 때만 사용)
  query_engine-*.node   : Prisma 데이터베이스 엔진 바이너리 (필수 유지)
  README.txt            : 본 사용 설명서 문서

  [서버 구동 시 자동 생성되는 폴더]
  ./data/               : SQLite 데이터베이스 파일 (sam.db) 보관 폴더
                          sp-server.lock 파일도 여기에 생깁니다 — 서버가 실행 중임을 표시해,
                          서버가 켜진 상태에서 sp-migrate.exe 가 DB 를 건드리지 못하게 막습니다.
                          서버를 정상 종료하면 자동으로 지워집니다.
  ./logs/               : 일별 회전 로그 파일 (sp-YYYY-MM-DD.log) 보관 폴더 (최근 2주/14일 자동 보관 및 경과 파일 자동 삭제)
                          sp-migrate.exe 의 업그레이드 기록(백업 경로, 실패 안내)도 같은 파일에 함께 남습니다.
  ./backups/            : 수동 백업(sp-backup.exe backup) 및 업그레이드 직전 백업 저장 폴더
                          - ./backups/sam_YYYYMMDD_HHMMSS.db          : sp-backup.exe 로 만든 수동 백업
                          - ./backups/pre-migrate/sam_YYYYMMDD_HHMMSS.db : sp-migrate.exe 가 업그레이드 직전에 만드는 백업
  ./data/backup/        : 매일 정해진 시각에 자동으로 만들어지는 백업 폴더
                          (./data/backup/YYYYMMDD/app.db.gz 형태, 기본 30일 보존 후 자동 삭제)
                          * 위 ./backups/ 와는 다른 폴더입니다. 자동 백업의 보존 기간 정리는
                            이 폴더만 대상으로 하므로 ./backups/ 의 파일은 자동으로 지워지지 않습니다.

--------------------------------------------------------------------
2. 서버 실행 방법 & 사내 네트워크(LAN) 접속
--------------------------------------------------------------------
  1) sp-server.exe 를 더블 클릭하여 실행합니다.
  2) 최초 실행 시 데이터베이스(./data/sam.db)가 자동 초기화되고 웹 서버(3000번 포트)가 동작합니다.
  3) 콘솔 창에 표시되는 IP 주소로 브라우저(Chrome/Edge 등)에서 접속합니다:
     - 호스트 PC 본인 접속 : http://localhost:3000
     - 사내 타 PC 접속     : http://<콘솔에표시된IP>:3000
  4) 사내 타 PC에서 접속이 안 될 경우 윈도우 방화벽 인바운드 규칙에서 TCP 3000번 포트를 허용해 주세요.

4. 신규 버전 업그레이드 및 종료 코드 안내
--------------------------------------------------------------------
[신규 버전으로 업그레이드하기]

    1) sp-server.exe 를 **먼저** 종료합니다. (콘솔 창에서 Ctrl+C, 또는 창을 닫습니다)
       * 이 순서를 반드시 지켜 주십시오. 서버가 켜진 채로 4)의 sp-migrate.exe 를 실행하면,
         업그레이드가 진행되는 그 몇 초 사이에 사용자가 저장한 일정이 조용히 사라질 수
         있습니다. 업그레이드 직전에 만드는 백업은 그 편집이 생기기 전에 떠 놓은 것이라
         이 손실은 백업으로도 되돌릴 수 없습니다.
       * 파일만 덮어쓰고 서버를 그대로 두면, 실행 중인 구버전 서버는 아무 이상 없이
         계속 동작하기 때문에 이 상황이 눈에 띄지 않습니다. 실제로 위험한 경우가 바로 이것입니다.
       * sp-migrate.exe 는 서버가 아직 실행 중인 것을 감지하면 DB 를 건드리지 않고
         종료 코드 7 로 멈춥니다. 다만 이 감지는 최선 노력이라, 종료 순서를 지키는 것이
         원칙입니다.
    2) 새로 받은 exe 파일들로 기존 파일을 덮어씁니다.
    3) sp-server.exe 를 실행합니다.
       - 그냥 시작되면 그대로 사용하십시오. 업그레이드할 것이 없다는 뜻입니다.
       - "데이터베이스 업그레이드가 필요합니다" 안내가 나오고 창이 닫히면 4)로 갑니다.
         (이 시점에는 sp-server.exe 프로세스가 이미 종료된 상태입니다. 창을 닫으라는
          뜻이 아니라, 안내에 적힌 다음 명령을 그대로 입력하면 됩니다.)
    4) sp-migrate.exe 를 실행합니다.
       > sp-migrate.exe
       - DB 를 backups/pre-migrate/ 에 자동 백업한 뒤 업그레이드합니다.
       - 실패하면 종료 코드 1 이고, 안내 문구로 원인을 구분할 수 있습니다.
         (아래 [종료 코드 안내]의 sp-migrate.exe 1번 항목 참고)
    5) sp-server.exe 를 다시 실행합니다.

    * 최초 설치(= DB 파일이 아직 없는 상태)에서는 sp-migrate.exe 가 아니라
      sp-server.exe 가 DB 를 직접 만듭니다. sp-migrate.exe 는 "이미 있는 DB 를
      업그레이드"하는 도구이지, DB 를 새로 만드는 도구가 아닙니다. DB 가 없는 상태로
      sp-migrate.exe 를 실행하면 DB 를 업그레이드하지 않고 안내만 출력합니다
      (종료 코드 2). 이때 ./data/ 폴더와 비어 있는 sam.db 파일은 만들어질 수
      있습니다 — 그 다음에 sp-server.exe 를 실행하면 정상적으로 초기화됩니다.
    * backups/pre-migrate/ 의 백업은 일자별 자동 백업의 보존 기간 정리 대상에서
      제외됩니다. 디스크가 부담되면 업그레이드가 안정된 뒤 수동으로 정리하십시오.

[종료 코드(Exit Code) 안내]

    sp-server.exe 와 sp-migrate.exe 는 종료될 때 아래 표의 번호를 상태 코드로 남깁니다.
    화면 안내만으로 원인이 분명하지 않을 때, 전화 지원 등에서 이 번호를 불러주면 빠르게
    상황을 판단할 수 있습니다. (윈도우에서 직전 실행 파일의 종료 코드 확인: 같은 창에서
    `echo %errorlevel%`)

    sp-server.exe
      0 : 정상 구동. 또는 DB 가 없어 새로 만든 뒤 정상 구동.
      1 : 예상하지 못한 오류로 종료. 아래 조건을 반드시 먼저 확인하십시오.
          - 화면(또는 logs/ 의 로그 파일)에 "데이터베이스 초기화에 실패했습니다" 안내가
            나온 경우에만, 그 안내에 적힌 대로 data/ 폴더의 DB 파일(및 -wal/-shm
            사이드카)을 지우고 sp-server.exe 를 다시 실행하십시오. 이 경우는 아직
            DB 를 만드는 중이었으므로 잃을 데이터가 없습니다.
          - 그 안내가 없이 exit 1 로 끝났다면 DB 파일을 절대 지우지 마십시오.
            데이터가 들어 있는 DB 일 수 있습니다. 화면과 logs/ 의 마지막 내용을 그대로
            담당 개발팀에 전달하십시오.
      3 : 기존 DB 에 적용되지 않은 업그레이드가 있습니다. sp-migrate.exe 를 실행하십시오.
      4 : 오래된 방식으로 만들어진 DB 라 지원하지 않습니다. 담당 개발팀에 문의하십시오.
      5 : 이 실행 파일이 알지 못하는 이력이 DB 에 있습니다 — 이 exe 보다 최신 DB 입니다.
          최신 exe 파일로 다시 받아 실행하십시오.
      6 : 스키마를 찾을 수 없거나, 설치에 마이그레이션 파일이 없습니다. 설치가 손상된
          것이므로 배포 매체를 다시 받아 재설치하십시오.

    sp-migrate.exe
      0 : 이미 최신 상태이거나, 업그레이드에 성공했습니다.
      1 : 실패했습니다. 화면 안내가 둘 중 하나를 알려줍니다.
          (가) "업그레이드 전 백업을 만들지 못했습니다" — 백업 자체가 안 된 것이므로
              업그레이드는 시작하지도 않았고 DB 는 전혀 변경되지 않았습니다. 디스크 여유
              공간, backups/pre-migrate/ 폴더 쓰기 권한, 동명 백업 파일 존재 여부를
              확인한 뒤 sp-migrate.exe 를 다시 실행하십시오.
          (나) "업그레이드가 실패했습니다" — 백업은 만들어졌지만 그 뒤 적용 도중 실패한
              것입니다. DB 가 중간 상태일 수 있습니다. 화면(또는 logs/ 의 로그 파일)에
              표시된 backups/pre-migrate/ 백업 파일로 아래 순서대로 복구하십시오.

                1) sp-server.exe 와 sp-migrate.exe 가 모두 종료된 것을 확인합니다.
                2) 아래 세 파일을 **모두** 지웁니다. (화면 안내에 경로가 그대로 나옵니다)
                     - data\sam.db
                     - data\sam.db-wal
                     - data\sam.db-shm
                   * -wal 파일을 남겨두면 안 됩니다. 다음 실행 때 SQLite 가 그 -wal 의
                     내용을 복원한 DB 에 다시 얹어, 절반만 적용된 상태가 되살아나거나
                     복원한 백업 자체가 깨질 수 있습니다.
                3) 화면에 표시된 backups\pre-migrate\sam_*.db 파일을 탐색기에서 복사해
                   data\sam.db 라는 이름으로 붙여넣습니다.
                4) sp-server.exe 를 실행해 정상 동작을 확인한 뒤, 원인을 담당 개발팀에
                   문의하십시오.

              * 이 복구에 sp-backup.exe restore 를 쓰지 마십시오. 그 명령은
                backups/pre-migrate/ 를 목록에 보여주지 않으며, 위 2)의 -wal/-shm 삭제도
                하지 않습니다. 업그레이드 실패 복구는 위 절차대로 파일을 직접 다루십시오.
      2 : DB 가 비어 있습니다. DB 를 새로 만드는 것은 sp-migrate.exe 의 역할이 아닙니다.
          sp-server.exe 를 먼저 실행해 DB 를 만드십시오.
      4 : 오래된 방식으로 만들어진 DB 라 지원하지 않습니다. 담당 개발팀에 문의하십시오.
      5 : 이 실행 파일이 알지 못하는 이력이 DB 에 있습니다(다운그레이드 상태). 최신 exe
          파일로 다시 받아 실행하십시오.
      6 : 스키마를 찾을 수 없거나, 설치에 마이그레이션 파일이 없습니다. 설치가 손상된
          것이므로 배포 매체를 다시 받아 재설치하십시오.
      7 : sp-server.exe 가 아직 실행 중입니다. DB 는 전혀 변경되지 않았습니다.
          서버를 종료한 뒤 sp-migrate.exe 를 다시 실행하십시오.
          * 서버를 이미 종료했는데도 계속 7 이 나오는 경우: 서버가 강제 종료되거나 콘솔 창이
            그냥 닫혀서, 실행 중임을 표시하는 잠금 파일(data\sp-server.lock)이 지워지지 않고
            남은 것입니다. 화면 안내에 그 파일의 전체 경로가 나옵니다. 서버가 종료된 것이
            확실하다면 그 파일을 지운 뒤 sp-migrate.exe 를 다시 실행하십시오.

    * 코드 2 와 7 은 sp-migrate.exe 에서만, 코드 3 은 sp-server.exe 에서만 나옵니다.

[업그레이드 관련 주의 사항 (알아두어야 할 두 가지)]

    - 업그레이드가 실패하면 이력에 "적용을 시작했지만 끝나지 않음" 표시가 남습니다.
      다시 시도해도 우리 도구는 문제없이 동작하지만, 이 상태로 정식 Prisma CLI
      (`prisma migrate deploy` 등)를 실행하면 그 도구는 이 표시를 "실패한 마이그레이션"
      으로 보고 오류(P3009)를 내며 멈춥니다. 정식 도구로 넘어갈 계획이 있다면 이 표시를
      먼저 해소해야 한다는 점을 알아 두십시오. (담당 개발팀 문의 사항)
    - 아주 드물게, 업그레이드 SQL 자체는 전부 성공했는데 그 마지막에 "적용 완료"로
      기록하는 단계만 실패할 수 있습니다. 이 경우 DB 는 이미 업그레이드된 상태인데
      이력에는 아직 안 된 것으로 남아, 다음 실행 때 같은 업그레이드를 처음부터 다시
      시도합니다. 이런 상황을 만나면 화면에 표시된 backups/pre-migrate/ 백업으로
      복구한 뒤 담당 개발팀에 문의하십시오. 복구 절차는 위 [종료 코드 안내]
      sp-migrate.exe 1번 (나) 항목과 같습니다 (파일 세 개 삭제 후 직접 복사).

5. 관리자 보조 도구 사용 설명서
--------------------------------------------------------------------
[A] DB 백업 및 특정 시점 복구 (sp-backup.exe)
    - 수동 백업 수행 (backups/ 폴더에 sam_YYYYMMDD_HHMMSS.db 스냅샷 생성):
      > sp-backup.exe backup

    - 백업 목록 확인:
      > sp-backup.exe list

    - 특정 날짜 백업 파일로 DB 복구 (복구 전 현재 DB는 자동 안전 백업됨):
      > sp-backup.exe restore sam_20260723_120000.db
      * 복구 후 sp-server.exe를 재시작해 주세요.
      * 이 명령은 backups/ 폴더 바로 아래의 파일만 다룹니다. 하위 폴더인
        backups/pre-migrate/ 의 업그레이드 직전 백업은 list 에도 나오지 않습니다.
        업그레이드 실패 복구는 위 4절 [종료 코드 안내] sp-migrate.exe 1번 (나) 항목의
        절차(파일 세 개 삭제 후 직접 복사)를 따르십시오.

[B] 관리자 비밀번호 재설정 (sp-reset-admin.exe)
    - sp-server.exe 가 실행 중일 때 (또는 최초 구동되어 DB가 생성된 후) 동작합니다.
    - 비밀번호 분실 시 원하는 새 암호로 즉시 변경 및 계정 잠금 해제:
      > sp-reset-admin.exe 원하는새비밀번호123!
    * sp-server.exe 가 실행 중인 상태에서 즉시 변경되며, 서버 재시작 없이 새로 지정한 비밀번호로 바로 로그인 가능합니다.
