====================================================================
  📌 SAM Scheduler (Seedcore Scheduler) 사내 서버 관리자 가이드
====================================================================

1. 디렉터리 구성 안내
--------------------------------------------------------------------
  sp-server.exe         : 메인 웹 서버 (웹 UI + REST API + DB 통합 단일 실행 파일)
  sp-backup.exe         : 관리자 전용 DB 백업 및 특정 시점 복구 CLI 도구
  sp-reset-admin.exe    : 관리자(admin) 비밀번호 즉시 재설정 CLI 도구
  sp-migrate.exe        : DB 스키마 업그레이드 도구 (새 버전 배포 후 필요할 때만 사용)
  query_engine-*.node   : Prisma 데이터베이스 엔진 바이너리 (필수 유지)
  README.txt            : 본 사용 설명서 문서

  * 배포용 zip 을 풀면 위 파일들이 seedcore-proj 폴더 안에 함께 들어 있습니다.
    이 폴더를 통째로 원하는 위치(예: D:\seedcore-proj)로 옮겨서 쓰십시오.
    아래 [서버 구동 시 자동 생성되는 폴더] 는 모두 exe 와 **같은 폴더 안에** 만들어지므로,
    파일을 흩어 놓거나 다운로드 폴더에서 그대로 실행하면 데이터 폴더가 엉뚱한 곳에 생깁니다.

  [서버 구동 시 자동 생성되는 폴더]
  ./data/               : SQLite 데이터베이스 파일 (sam.db) 보관 폴더
                          sp-server.lock / sp-migrate.lock 파일도 여기에 생깁니다 — 어느 프로그램이
                          DB 를 쓰고 있는지 표시하는 파일입니다. 서버를 Ctrl+C 로 종료하면 자동으로
                          지워집니다. 창을 X 로 닫으면 남는데, 드물게 다음 실행을 막는 원인이 됩니다.
                          (2절 [서버를 종료할 때] 와 [한 번에 하나만 실행됩니다] 참고)
  ./logs/               : 일별 회전 로그 파일 (sp-YYYY-MM-DD.log) 보관 폴더 (최근 2주/14일 자동 보관 및 경과 파일 자동 삭제)
                          sp-migrate.exe 의 업그레이드 기록(백업 경로, 실패 안내)도 같은 파일에 함께 남습니다.
  ./backups/            : 수동 백업(sp-backup.exe backup) 및 업그레이드 직전 백업 저장 폴더
                          - ./backups/sam_YYYYMMDD_HHMMSS.db          : sp-backup.exe 로 만든 수동 백업
                          - ./backups/sam_before_restore_YYYYMMDD_HHMMSS.db : sp-backup.exe restore 가
                                                                        복구 직전에 자동으로 남기는 백업
                          - ./backups/pre-migrate/sam_YYYYMMDD_HHMMSS.db : sp-migrate.exe 가 업그레이드 직전에 만드는 백업
                          * 위 두 가지 백업 옆에 같은 이름의 "-wal" 파일이 함께 생길 수 있습니다.
                            아직 본체에 반영되지 않은 최근 저장 내용이 들어 있는 짝꿍 파일이므로
                            지우지 마십시오. 복구할 때 자동으로 함께 되돌아갑니다.
  ./data/backup/        : 매일 정해진 시각에 자동으로 만들어지는 백업 폴더
                          (./data/backup/YYYYMMDD/app.db.gz 형태, 기본 30일 보존 후 자동 삭제)
                          * 위 ./backups/ 와는 다른 폴더입니다. 자동 백업의 보존 기간 정리는
                            이 폴더만 대상으로 하므로 ./backups/ 의 파일은 자동으로 지워지지 않습니다.

2. 서버 실행 방법 & 사내 네트워크(LAN) 접속
--------------------------------------------------------------------
  1) sp-server.exe 를 더블 클릭하여 실행합니다.
  2) 최초 실행 시 데이터베이스(./data/sam.db)가 자동 초기화되고 웹 서버(3000번 포트)가 동작합니다.
  3) 콘솔 창에 표시되는 IP 주소로 브라우저(Chrome/Edge 등)에서 접속합니다:
     - 호스트 PC 본인 접속 : http://localhost:3000
     - 사내 타 PC 접속     : http://<콘솔에표시된IP>:3000
  4) 사내 타 PC에서 접속이 안 될 경우 윈도우 방화벽 인바운드 규칙에서 TCP 3000번 포트를 허용해 주세요.

[서버를 종료할 때 — 반드시 콘솔 창에서 Ctrl+C]

  서버를 멈출 때는 **sp-server.exe 의 콘솔(검은) 창을 클릭해 활성화한 뒤 Ctrl+C 를 누르십시오.**
  창 오른쪽 위의 X 버튼으로 닫거나, 작업 관리자에서 강제 종료하지 마십시오.

  [왜 그래야 하는가]
    서버는 실행 중인 동안 "지금 내가 이 데이터베이스를 쓰고 있다" 는 표시로 data\sp-server.lock
    파일을 만들어 둡니다. 이 파일에는 서버의 프로세스 번호(PID)가 적혀 있습니다.

    Ctrl+C 로 종료하면 서버가 그 파일을 스스로 지우고 정상 종료(코드 0)로 끝납니다.
    창을 X 로 닫거나 작업 관리자로 강제 종료하면 정리 절차가 아예 실행되지 않아 파일이 남습니다.

    남은 파일이 곧바로 문제를 일으키지는 않습니다. 다음 프로그램은 파일이 있는지가 아니라 그
    PID 가 **아직 살아 있는지**를 확인하므로, 이미 죽은 서버의 잠금은 무해하게 무시됩니다.
    문제는 윈도우가 그 PID 를 뒤에 실행된 **다른 프로그램에 재사용**했을 때입니다. 그러면 서버가
    꺼져 있는데도 "다른 프로그램이 데이터베이스를 쓰고 있다" 고 판단해, 아래 작업이 아무것도
    하지 않은 채 종료 코드 7 로 멈춥니다.
      - sp-server.exe                  → 서버를 다시 켤 수 없습니다
      - sp-migrate.exe                 → 업그레이드를 할 수 없습니다
      - sp-backup.exe 의 backup/restore → 백업과 복구를 할 수 없습니다

    드문 경우이지만, 하필 업그레이드나 백업을 하려는 순간에 원인을 알 수 없는 모습으로 나타납니다.
    Ctrl+C 로 끄면 이 가능성이 아예 없어집니다.

  [그래도 막혔을 때]
    화면 안내에 지워야 할 잠금 파일의 전체 경로가 그대로 나옵니다. 서버가 정말 꺼져 있는 것이
    확실하다면 그 파일을 지우고 다시 실행하면 됩니다
    (4절 [종료 코드 안내] 의 7번 항목 참고).

  * Ctrl+C 를 누르면 서버가 즉시 종료됩니다. 기다려야 하는 시간은 없습니다.
    이미 저장된 데이터는 그대로 유지됩니다.
  * 서버를 켜 둔 채로 해도 되는 일과 반드시 끈 뒤에 해야 하는 일은 바로 아래
    [한 번에 하나만 실행됩니다] 에 정리되어 있습니다.

[한 번에 하나만 실행됩니다]

  데이터베이스를 직접 다루는 두 프로그램(sp-server.exe, sp-migrate.exe)은 **둘 중 하나만, 하나씩**
  실행할 수 있습니다. 하나가 실행 중일 때 다른 하나(또는 같은 것을 또) 실행하면, 그 프로그램은
  데이터베이스를 건드리지 않고 안내를 출력한 뒤 종료 코드 7 로 멈춥니다.

    - sp-server.exe 실행 중  → sp-server.exe 를 또 실행할 수 없습니다 (이미 켜진 서버를 쓰십시오)
    - sp-server.exe 실행 중  → sp-migrate.exe 를 실행할 수 없습니다 (서버를 먼저 종료하십시오)
    - sp-migrate.exe 실행 중 → sp-server.exe 를 실행할 수 없습니다 (업그레이드가 끝난 뒤 실행하십시오)
    - sp-migrate.exe 실행 중 → sp-migrate.exe 를 또 실행할 수 없습니다 (끝날 때까지 기다리십시오)

  이유: 업그레이드는 데이터베이스 구조를 여러 단계에 걸쳐 바꾸는 작업입니다. 그 사이에 다른
  프로그램이 같은 데이터베이스를 고치면, 그때 저장된 내용이 사라지거나 구조가 절반만 바뀐 상태로
  남을 수 있습니다. 이 손실은 업그레이드 직전 백업으로도 되돌릴 수 없습니다.

  * sp-reset-admin.exe 는 이 제한과 무관합니다 (구조를 바꾸지 않습니다).
  * sp-backup.exe 의 list 는 목록만 읽으므로 언제든 실행할 수 있습니다. 다만 backup 과
    restore 는 데이터베이스 파일을 직접 다루므로 이 제한을 함께 받습니다 — sp-server.exe 나
    sp-migrate.exe 가 실행 중이면 아무 작업도 하지 않고 안내를 출력한 뒤 종료 코드 7 로 멈춥니다.
    서버를 끄지 않고 백업을 받는 방법은 5절 [A] 에 정리되어 있습니다.

4. 신규 버전 업그레이드 및 종료 코드 안내
--------------------------------------------------------------------
[신규 버전으로 업그레이드하기]

    1) sp-server.exe 를 **먼저** 종료합니다. — **반드시 콘솔 창에서 Ctrl+C 를 누르십시오.**
       * 창을 X 로 닫거나 작업 관리자로 강제 종료하면 잠금 파일(data\sp-server.lock)이
         지워지지 않고 남습니다. 그 상태에서 PID 가 다른 프로그램에 재사용되면, 서버가 꺼져
         있는데도 아래 4)의 sp-migrate.exe 가 종료 코드 7 로 멈춰 업그레이드를 진행할 수
         없습니다. 자세한 이유와 대처는 2절 [서버를 종료할 때] 를 보십시오.
       * 이 순서를 반드시 지켜 주십시오. 서버가 켜진 채로 4)의 sp-migrate.exe 를 실행하면,
         업그레이드가 진행되는 그 몇 초 사이에 사용자가 저장한 일정이 조용히 사라질 수
         있습니다. 업그레이드 직전에 만드는 백업은 그 편집이 생기기 전에 떠 놓은 것이라
         이 손실은 백업으로도 되돌릴 수 없습니다.
       * 파일만 덮어쓰고 서버를 그대로 두면, 실행 중인 구버전 서버는 아무 이상 없이
         계속 동작하기 때문에 이 상황이 눈에 띄지 않습니다. 실제로 위험한 경우가 바로 이것입니다.
       * sp-migrate.exe 는 서버가 아직 실행 중인 것을 감지하면 DB 를 건드리지 않고
         종료 코드 7 로 멈춥니다. 다만 이 감지는 최선 노력이라, 종료 순서를 지키는 것이
         원칙입니다.
    2) 새로 받은 exe 파일들로 기존 파일을 덮어씁니다.
    3) sp-server.exe 를 실행합니다.
       - 그냥 시작되면 그대로 사용하십시오. 업그레이드할 것이 없다는 뜻입니다.
       - "데이터베이스 업그레이드가 필요합니다" 안내가 나오고 창이 닫히면 4)로 갑니다.
         (이 시점에는 sp-server.exe 프로세스가 이미 종료된 상태입니다. 창을 닫으라는
          뜻이 아니라, 안내에 적힌 다음 명령을 그대로 입력하면 됩니다.)
    4) sp-migrate.exe 를 실행합니다.
       > sp-migrate.exe
       - DB 를 backups/pre-migrate/ 에 자동 백업한 뒤 업그레이드합니다.
       - 실패하면 종료 코드 1 이고, 안내 문구로 원인을 구분할 수 있습니다.
         (아래 [종료 코드 안내]의 sp-migrate.exe 1번 항목 참고)
    5) sp-server.exe 를 다시 실행합니다.

    * 최초 설치(= DB 파일이 아직 없는 상태)에서는 sp-migrate.exe 가 아니라
      sp-server.exe 가 DB 를 직접 만듭니다. sp-migrate.exe 는 "이미 있는 DB 를
      업그레이드"하는 도구이지, DB 를 새로 만드는 도구가 아닙니다. DB 가 없는 상태로
      sp-migrate.exe 를 실행하면 DB 를 업그레이드하지 않고 안내만 출력합니다
      (종료 코드 2). 이때 ./data/ 폴더와 비어 있는 sam.db 파일은 만들어질 수
      있습니다 — 그 다음에 sp-server.exe 를 실행하면 정상적으로 초기화됩니다.
    * backups/pre-migrate/ 의 백업은 일자별 자동 백업의 보존 기간 정리 대상에서
      제외됩니다. 디스크가 부담되면 업그레이드가 안정된 뒤 수동으로 정리하십시오.

[종료 코드(Exit Code) 안내]

    sp-server.exe 와 sp-migrate.exe 는 종료될 때 아래 표의 번호를 상태 코드로 남깁니다.
    화면 안내만으로 원인이 분명하지 않을 때, 전화 지원 등에서 이 번호를 불러주면 빠르게
    상황을 판단할 수 있습니다. (윈도우에서 직전 실행 파일의 종료 코드 확인: 같은 창에서
    `echo %errorlevel%`)

    sp-server.exe
      0 : 정상 구동(또는 DB 가 없어 새로 만든 뒤 정상 구동) 후, 관리자가 Ctrl+C 로 종료한 경우.
          * 서버는 계속 켜져 있는 프로그램이므로 이 번호는 종료했을 때 남습니다. 창을 X 로 닫거나
            강제 종료하면 이 번호가 남지 않습니다 — 2절 [서버를 종료할 때] 참고.
      1 : 예상하지 못한 오류로 종료. 아래 조건을 반드시 먼저 확인하십시오.
          - 화면(또는 logs/ 의 로그 파일)에 "데이터베이스 초기화에 실패했습니다" 안내가
            나온 경우에만, 그 안내에 적힌 대로 data/ 폴더의 DB 파일(및 -wal/-shm
            사이드카)을 지우고 sp-server.exe 를 다시 실행하십시오. 이 경우는 아직
            DB 를 만드는 중이었으므로 잃을 데이터가 없습니다.
          - 그 안내가 없이 exit 1 로 끝났다면 DB 파일을 절대 지우지 마십시오.
            데이터가 들어 있는 DB 일 수 있습니다. 화면과 logs/ 의 마지막 내용을 그대로
            담당 개발팀에 전달하십시오.
      3 : 기존 DB 에 적용되지 않은 업그레이드가 있습니다. sp-migrate.exe 를 실행하십시오.
      4 : 오래된 방식으로 만들어진 DB 라 지원하지 않습니다. 담당 개발팀에 문의하십시오.
      5 : 이 실행 파일이 알지 못하는 이력이 DB 에 있습니다 — 이 exe 보다 최신 DB 입니다.
          최신 exe 파일로 다시 받아 실행하십시오.
      6 : 스키마를 찾을 수 없거나, 설치에 마이그레이션 파일이 없습니다. 설치가 손상된
          것이므로 배포 매체를 다시 받아 재설치하십시오.
      7 : 다른 프로그램이 데이터베이스를 쓰고 있어 서버를 시작하지 않았습니다.
          DB 는 전혀 변경되지 않았습니다. 화면 안내가 둘 중 하나를 알려줍니다.

[업그레이드 관련 주의 사항 (알아두어야 할 두 가지)]

    - 아주 드물게, 업그레이드 SQL 자체는 전부 성공했는데 그 마지막에 "적용 완료"로

[A] DB 백업 및 특정 시점 복구 (sp-backup.exe)
    - 수동 백업 수행 (backups/ 폴더에 sam_YYYYMMDD_HHMMSS.db 스냅샷 생성):
      > sp-backup.exe backup
      * 같은 이름의 "-wal" 파일이 함께 만들어질 수 있습니다. 백업의 일부이므로
        지우지 마십시오 (아직 본체에 반영되지 않은 최근 저장 내용이 여기 들어 있습니다).
      * sp-server.exe 나 sp-migrate.exe 가 실행 중이면 백업을 만들지 않고 종료 코드 7 로
        멈춥니다. 서버가 켜진 채로 파일을 복사하면, 복사가 끝나기 전에 서버가 내용을 옮겨
        적어 앞뒤가 맞지 않는 백업이 될 수 있기 때문입니다. 그런 백업은 정작 복구할 때가
        되어서야 쓸 수 없다는 것을 알게 됩니다.

    - 서버를 끄지 않고 백업을 받으려면 (아래 둘 다 서버가 직접 뜨는 방식이라 안전합니다)
      1) 자동 백업이 이미 돌고 있습니다.
         서버는 매일 정해진 시각(기본 새벽 4시)에 아래 위치로 백업을 남깁니다.
           ./data/backup/YYYYMMDD/app.db.gz        (기본 30일 보관 후 자동 삭제)
           ./data/backup/YYYYMMDD/app.db.gz.sha256 (무결성 확인용 해시)
         복구에 쓰려면 app.db.gz 의 압축을 풀어 data\sam.db 로 넣으십시오. 이때는
         4절 [직접 복구하는 방법] 과 똑같이 -wal/-shm 을 먼저 지워야 합니다
         (sp-backup.exe restore 는 backups/ 폴더의 파일만 다룹니다).
      2) 지금 당장 한 부 받고 싶다면 서버의 관리자 API 를 호출하십시오. 같은 방식의 백업이
         즉시 만들어지고, 응답(JSON)에 만들어진 파일 경로와 크기, 해시가 담겨 옵니다.
           POST http://<서버주소>:3000/api/v1/admin/health/backup/run
         * ADMIN 계정으로 로그인한 세션 쿠키가 필요하며, CSRF 방어 때문에 Origin 헤더도
           서버 주소와 같아야 합니다. 서버 PC 에서 실행하는 예:
           > curl.exe -X POST http://localhost:3000/api/v1/admin/health/backup/run
                      -H "Origin: http://localhost:3000" -b "sam_sid=<로그인 세션 쿠키>"
      3) 아니면 sp-server.exe 를 종료한 뒤 sp-backup.exe backup 을 실행하십시오.

    - 백업 목록 확인:
      > sp-backup.exe list
      * backups/ 바로 아래의 수동 백업과 backups/pre-migrate/ 의 업그레이드 직전 백업을
        모두 보여주며, 종류별로 묶어 표시합니다. 목록 맨 아래에 그대로 복사해 쓸 수 있는
        restore 명령 예시가 함께 나옵니다.

    - 특정 날짜 백업 파일로 DB 복구 (복구 전 현재 DB는 자동 안전 백업됨):
      > sp-backup.exe restore sam_20260723_120000.db
      > sp-backup.exe restore pre-migrate/sam_20260723_120000.db
      * list 에 보이는 이름을 하위 폴더까지 그대로 넘기십시오.
      * 복구 전 현재 DB 는 backups/sam_before_restore_*.db 로 자동 저장됩니다
        (-wal 짝꿍 파일까지 함께 저장하므로 그대로 되돌릴 수 있습니다).
        화면에 되돌리는 명령이 그대로 표시됩니다.
      * 복구할 때 data/sam.db-wal 과 data/sam.db-shm 을 자동으로 정리합니다.
        (이 정리를 하지 않으면 SQLite 가 옛 데이터를 복구한 DB 위에 다시 얹어
         복구가 무효가 되거나 파일이 깨집니다. 직접 지우실 필요 없습니다.)
      * sp-server.exe 나 sp-migrate.exe 가 실행 중이면 아무 작업도 하지 않고 안내를
        출력한 뒤 종료 코드 7 로 멈춥니다. 두 프로그램을 먼저 종료하십시오.
        종료한 것이 확실한데도 계속 7 이 나오면 잠금 파일(data\sp-server.lock 또는
        data\sp-migrate.lock)이 남은 것이며, 화면 안내에 지울 파일의 전체 경로가 나옵니다.
      * 복구 후 sp-server.exe를 재시작해 주세요.

    [종료 코드]

      1 : 백업 파일이나 DB 파일을 찾을 수 없는 등 입력 오류 (DB 는 변경되지 않았습니다)
      7 : sp-server.exe 또는 sp-migrate.exe 가 실행 중이라 backup / restore 를 하지
          않았습니다 (DB 도 백업 파일도 전혀 변경되지 않았습니다).
          화면 안내에 종료할 프로그램과, 그래도 계속 7 이 나올 때 지울 잠금 파일의 전체
