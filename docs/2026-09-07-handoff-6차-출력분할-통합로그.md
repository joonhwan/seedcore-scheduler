## 2. 6차의 범위 — 출력 셋과 통합 로그 하나

확정명세 §3(③)과 §9 그대로입니다. **데이터베이스 변경이 없습니다.**

간트 요청(③)은 네 갈래인데 **화면 배율(③-가)만 4차에서 끝났고 출력 쪽 셋이 남았습니다.**

- **③-나 "지금 화면 그대로" 내보내기** — 현재 배율과 펼침 상태를 출력물에 담는다.
- **③-다 기간을 지정한 출력** — 시작일~종료일을 직접 고르고, 빠른 버튼(전체 기간 / 이번 달 / 이번 주 / 앞으로 4주)을 함께 둔다.
- **③-라 여러 장으로 잘라 PDF 한 부로** — "4개월을 4주씩 넉 장", "한 달을 1주씩 다섯 장"처럼 자동 분할하되 **결과물은 PDF 하나**다(파일이 흩어지면 안 된다는 것이 ㉲ 회신의 요지). 쪽마다 그 쪽이 담은 기간과 프로젝트 이름을 머리에 찍고, A4 가로를 기본으로 하되 방향·크기를 고를 수 있게 한다.
- **5-2 전 프로젝트 통합 로그 팝업** — 프로젝트별 이력 화면은 이미 있고(`apps/web/src/pages/ProjectHistoryPage.tsx`), 전 프로젝트를 아우르는 통합 로그와 팝업 형태가 신규다.

### 2.1 조사해 둔 재료 — 다시 찾지 않아도 되는 것

**출력 쪽은 본뜰 것이 이미 다 있습니다.**

| 파일 | 역할 |
|---|---|
| `apps/web/src/lib/ganttExport.ts` | 순수 계산: `computeExportSize`, `collapsedIdsForDepth`, `treeMaxDepth`, `buildExportFilename`, 상수 `EXPORT_MAX_EDGE`(16000)·`EXPORT_PIXEL_RATIO`(2) |
| `apps/web/src/lib/ganttExport.test.ts` | 위 함수들의 시험 (본뜰 형태) |
| `apps/web/src/lib/exportGanttImage.ts` | `html-to-image` 의 `toPng` 로 화면 밖 간트를 찍는다 |
| `apps/web/src/lib/exportGanttExcel.ts` | `exceljs` 로 엑셀을 만든다 |
| `apps/web/src/components/GanttExportDialog.tsx` | 단위·트리 단계·테마를 고르는 대화상자 (여기에 기간과 분할이 붙는다) |
| `apps/web/src/components/GanttExportView.tsx` | 화면 밖에 그리는 간트 |
| `apps/web/src/components/ExportMenu.tsx` | 내보내기 메뉴 |

- **PDF 라이브러리를 새로 들여와야 합니다.** 폐쇄망이라 화면이 외부에서 내려받는 방식은 쓸 수 없고, 개발 단계에서 번들에 함께 묶습니다. **`exceljs` 가 이미 그 방식으로 들어와 있으므로 배포 구조는 달라지지 않습니다.**
- 흐름은 "구간마다 `toPng` 로 이미지를 만들어 PDF 쪽에 넣는" 것이라, 검증된 이미지 내보내기 코드를 그대로 재사용합니다.
- `EXPORT_MAX_EDGE = 16000` 이 있는 이유를 확인하십시오. 기간을 자르는 목적 자체가 이 한계와 인쇄 가독성입니다.

**통합 로그 쪽의 재료도 준비되어 있습니다.**

- 기록은 이미 쌓입니다. `AuditLog` 모델(`apps/api/prisma/schema.prisma`)에 `actorId`·`action`·`targetType`·`targetId`·`ip`·`userAgent`·`occurredAt`·`payloadJson` 이 있고 **`@@index([occurredAt])` 가 이미 걸려 있습니다** — 시각 역순 조회에 색인이 준비되어 있으니 마이그레이션이 필요 없습니다.
- **읽는 기능만 없습니다.** `apps/api/src` 의 어느 컨트롤러도 `audit_logs` 를 조회하지 않습니다(5차에서 감사로그를 확인할 때 Prisma Studio 로 DB 를 직접 열어야 했던 이유입니다).
- `AuditAction` enum 은 `packages/shared/src/index.ts` 에 있고 5차에서 `SERVER_NOTICE_CREATE`·`SERVER_NOTICE_CANCEL` 이 더해져 서른아홉 개입니다. 화면에 한국어로 보여줄 것이라면 그 매핑을 어디에 둘지가 판단 지점입니다.
- 새 라우트에는 **ADMIN 전용 여부를 먼저 정하십시오.** 감사로그에는 다른 사람의 IP 와 행위가 들어 있어 일반 사용자에게 그대로 열 성격이 아닙니다. 확정명세는 이 점을 명시하지 않았으므로 브레인스토밍에서 확인받아야 합니다.

## 3. 배포 전에 남은 일 둘 (6차와 별개)

1. **사용설명서(`docs/user-guide.md`)에 2·3·4차 기능이 아직 없고, 여기에 5차가 더해졌습니다.** 그룹 관리·사용자 상세·"퇴사자 포함" 보기·계정 정리가 §8.4 의 열거에서 빠져 있고, 목록 스크롤(§3.1)과 간트 배율(§5.2)은 옛 서술 그대로입니다. **스크린샷 두 장**(`docs/images/02_projects_list.png` 과 간트 화면)도 다시 찍어야 합니다. 사용자와 합의한 순서는 **6차까지 끝낸 뒤 한 번에 채우는 것**입니다(스크린샷을 두 번 찍지 않으려고).
2. **배포판 예행 연습이 최신 코드로 수행되지 않았습니다.** `dist-release/` 의 zip 은 커밋 `1b8cde6`(2026-09-03) 기준입니다. 사용자 요청으로 5차·6차를 끝낸 뒤로 미뤘습니다. 그때 확인할 것: 고객 서버에 **마이그레이션 두 개가 순서대로** 적용되는지(2차·3차의 `user_groups_and_retired_at` 과 5차의 `server_notices`), `sp-server.exe` 가 종료 코드 3으로 멈추는지, `sp-migrate.exe` 가 `backups/pre-migrate/` 에 스냅샷을 뜨고 행 수를 보존하는지.

   **fly.io 는 사정이 다릅니다.** 2차·3차 마이그레이션은 `origin/master` 에 2026-09-04 에 올라가 이미 적용되었고, 5차는 머지하는 순간 자동 적용됩니다. 두 환경의 상태가 다른 것을 헷갈리지 마십시오.

- **확정명세 §9 표의 5차 상태가 "대기" 입니다.** "완료 (2026-09-07)" 로 고치십시오.
- **확정명세에 5차 완료 내용 절이 없습니다.** 1·2·3·4차는 각각 있습니다(§9 의 "N차 완료 내용"). 고객이 읽는 문서이므로 같은 형태로 쓰십시오.

- **확정명세 §5-나와 달라진 점을 고객에게 전달해야 합니다.** 명세는 "**편집 중인 내용이 있으면** 저장하지 않은 변경이 있습니다를 함께 띄운다"인데, 구현은 **조건 없이 항상** 저장 안내를 띄웁니다. 편집 상태를 아는 화면이 프로젝트 상세 하나뿐이라 조건을 걸면 나머지 화면에서 안내가 조용해지기 때문입니다(설계 문서 §4.4). 조건이 빠지는 대신 놓치는 자리가 없어집니다.

- **㉱ (고객 회신 대기)**: 기존 내보내기 기능(간트 PNG·엑셀의 일·주·월·분기 단위 출력)을 **먼저 써 보신 뒤 부족한 점을 알려주시기로** 되어 있습니다. **이 회신이 6차 ③-나·다·라의 범위를 조정할 수 있으므로**, 6차를 브레인스토밍할 때 회신이 왔는지 먼저 확인하십시오.

## 6. 5차에서 알아낸 것 — 다음 차수에 쓸 것

- **Windows git-bash 에서 curl 로 한글 JSON 본문을 보내면 인코딩이 깨집니다.** 5차에서 curl 로 등록한 예고의 문구가 DB 에 `EFBFBD`(U+FFFD 대체 문자)로 저장되었습니다. 브라우저로 등록한 것은 정상 UTF-8 이었으므로 **애플리케이션은 문제가 없습니다.** 한글이 든 API 검증은 curl 대신 브라우저나 node 스크립트로 하십시오.
- **브라우저 자동화는 Playwright MCP 가 됩니다.** Chrome 확장(`claude-in-chrome`)은 연결되지 않았고, `.mcp.json` 의 Playwright 는 세션 시작 시 한 번 시간이 걸린 뒤 동작했습니다. 스냅샷과 스크린샷이 `.playwright-mcp/` 에 떨어집니다(git 무시 대상).
- **개발 DB 의 `admin` 비밀번호는 `admin` 입니다.**
- **마이그레이션 SQL 을 적용한 뒤에 손으로 고치면 Prisma 체크섬이 어긋납니다.** 5차에서 `CHECK` 를 손으로 더한 뒤 그 일이 생겨, `_prisma_migrations` 의 해당 행을 지우고 빈 테이블을 DROP 한 뒤 `prisma migrate deploy` 로 재적용해 맞췄습니다. **그대로 두면 다음번에 스키마를 바꿀 때 "migration has been modified" 로 거부됩니다.** 손으로 고칠 일이 생기면 적용 **전에** 고치거나, 고친 뒤 위 절차로 되돌리십시오.
- **`prisma migrate reset --force` 를 검증에 쓰지 마십시오.** 개발 DB 를 지워 시험 데이터가 함께 사라집니다. 임시 경로에 `DATABASE_URL` 을 걸고 `prisma migrate deploy` 를 돌리면 같은 검증을 안전하게 할 수 있습니다.
- **`@NoSessionTouch()` 패턴**: 사용자가 조작하지 않았는데도 주기적으로 오는 요청(폴링)이 `lastSeenAt` 을 올리면 접속자 판정이 무의미해집니다. 5차가 그 표시를 만들어 뒀으니(`apps/api/src/auth/auth.guard.ts`), **앞으로 폴링 라우트를 더할 때 이 표시를 붙일지 반드시 판단하십시오.** 붙이지 않아도 에러가 나지 않아 조용히 망가집니다. 부착 여부를 못 박는 시험이 `apps/api/src/server-notices/server-notices.controller.test.ts` 에 있습니다.
- **셸 heredoc 으로 한국어 여러 줄을 넘기면 이 환경에서 파싱이 깨집니다.** 커밋 메시지는 파일에 쓴 뒤 `git commit -F <경로>` 로 넘기십시오.

## 7. 작업 환경 주의사항

- **`prisma migrate dev` 는 개발 서버를 끄고 돌립니다.** SQLite 는 단일 writer 라 `pnpm dev` 나 Prisma Studio 가 DB 핸들을 쥐고 있으면 락이 걸립니다.
- **`packages/shared` 에 새 export 를 더하면 vite 사전 번들 캐시를 지워야 합니다.** 안 지우면 그 심볼이 조용히 `undefined` 가 되어 **에러 없이 화면만 빈 채로** 뜹니다. `pnpm dev` 로 띄우면 `scripts/dev.mjs` 가 매번 지웁니다.
- **API 는 3000 이 뜰 때까지 시간이 걸립니다.** `curl http://localhost:3000/api/v1/health` 가 200 을 줄 때까지 기다리십시오.
- **브라우저로 3000 을 직접 열지 마십시오.** exe 빌드가 남긴 `apps/api/public` 의 옛 화면이 뜹니다.
- 코드 수정 후 `pnpm -r typecheck`, 시험은 `pnpm -r test`(현재 779건).
- 셸에서 `cd` 를 독립적으로 쓰지 않고 절대 경로를 씁니다.

## 8. 권해 두는 스킬

- **`superpowers:brainstorming`** — **가장 먼저 부르십시오.** 6차는 판단할 것이 여럿입니다: 통합 로그의 권한 범위(ADMIN 전용인지), PDF 라이브러리 선택, 분할 기준을 사용자가 고르는 방식, "지금 화면 그대로"가 배율만인지 펼침 상태까지인지. ㉱ 회신이 왔는지도 이 단계에서 확인하십시오.
- **`superpowers:writing-plans`** — 설계를 승인받은 뒤에 부릅니다.
- **`superpowers:subagent-driven-development`** — 5차를 이 방식으로 실행했고 잘 맞았습니다(작업마다 새 에이전트 + 검토). 계획에 실제 코드를 적어 두면 저비용 모델로도 정확히 옮깁니다.
- **`superpowers:test-driven-development`** — 기간 분할 계산은 경계가 많아(마지막 구간이 짧을 때, 프로젝트 기간이 분할 단위보다 짧을 때) 순수 함수로 떼어 시험하기에 알맞습니다. `ganttExport.test.ts` 가 본뜰 형태입니다.
- **`superpowers:systematic-debugging`** — 4차에서 프레임 단위로 재어 간트 깜박임의 원인을 잡았습니다. 추측으로 고치지 말고 재는 습관이 이 저장소에서 잘 통합니다.
- **`sam-troubleshooting`** (프로젝트 스킬) — `database is locked`, 옛 빌드 실행, 빈 화면 같은 함정.
- **`mirero-tools:easy-korean-doc`** — 고객에게 보낼 문서(§4 의 확정명세 갱신)를 다듬을 때.
