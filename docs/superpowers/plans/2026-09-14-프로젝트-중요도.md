# 프로젝트 중요도와 목록 인플레이스 편집 — 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 프로젝트에 조직 공통의 중요도 값을 두어 목록에서 정렬·표시하고, MANAGER 가 목록 화면을 벗어나지 않고 명칭·설명·중요도를 고칠 수 있게 한다.

**Architecture:** `projects` 테이블에 부호 있는 정수 컬럼 하나를 추가한다. 중요도는 특별한 정렬 층이 아니라 **정렬 가능한 컬럼 하나**이며, 이미 완성된 정렬 기억 기능(`projectListSort.ts`) 위에 얹힌다. 권한은 상세 화면에 이미 있는 `canManageProject`(MANAGER 이거나 관리자 모드 ADMIN)를 프로젝트 속성 편집까지 넓히는 형태이며, 한 API 안에서 필드마다 판단이 갈린다.

**Tech Stack:** Node 22.13+, NestJS 10, Prisma 5.22, SQLite(WAL), React 18, Vite 5, Tailwind, TanStack Query, Zod, vitest

**Spec:** `docs/superpowers/specs/2026-09-14-프로젝트-중요도-design.md`

- **`req.adminMode === true` 상태의 데이터 수정은 `ADMIN_OVERRIDE_EDIT` 감사로그를 추가로 남긴다** (`AGENTS.md` §4.4).
- **수정 요청은 `expectedUpdatedAt` 을 받아 불일치 시 409 를 던진다** (`AGENTS.md` §4.5).
- **모든 작업 뒤 `pnpm -r typecheck` 를 돌린다** (`AGENTS.md` §4.1).
- **TDD**: 테스트를 먼저 쓰고, 실패를 눈으로 확인한 뒤 최소 구현을 한다.
- **중요도 값**: 미지정 `0`, 최저 `-3`, 최고 `+3`. 부호 있는 정수로 저장한다.
- **DB `CHECK` 제약을 걸지 않는다.** 범위 판단은 Zod 에만 둔다 (설계 §3.2).

```ts
/**
 * 프로젝트 중요도(우선순위).
 *
 * 팀장·관리자가 그때그때 조정하며, 여러 프로젝트에 걸쳐 있는 멤버가 무엇을 먼저
 * 진행해야 하는지 알아차리게 하는 조직 공통 값이다. 개인의 화면 설정이 아니다.
 *
 * **0 이 "지정하지 않음"이자 "보통"이다.** 부호 있는 정수로 둔 덕분에 값을 매기지 않은
 * 프로젝트가 저절로 가운데에 놓인다. 미지정 항목을 맨 위로 올릴지 맨 아래로 내릴지
 * 고민할 필요가 없다.
 *
 * 단계를 넓힐 계획이 있어 **DB 에는 `CHECK` 제약을 걸지 않았다.** SQLite 는 제약을 바꾸려면
 * 테이블을 다시 만들어야 하기 때문이다. 범위를 아는 곳은 여기뿐이므로, 넓힐 때는 이 파일의
 * 상수와 라벨 표만 고치면 된다.
 */
export const PROJECT_PRIORITY_MIN = -3;
export const PROJECT_PRIORITY_MAX = 3;

const PROJECT_PRIORITY_LABELS: Readonly<Record<number, string>> = {
  3: '최우선',
  2: '높음',
  1: '다소 높음',
  0: '보통',
  [-1]: '다소 낮음',
  [-2]: '낮음',
  [-3]: '최하',
};

/**
 * 저장값을 화면에 보일 말로 옮긴다. 숫자만으로는 높은 쪽인지 낮은 쪽인지 즉시 읽히지 않는다.
 *
 * 표에 없는 값은 부호를 붙인 숫자를 그대로 돌려준다. 범위를 넓혔다 되돌리거나 DB 를 직접
 * 고친 경우에도 목록 화면은 떠야 하기 때문이다.
 */
export function projectPriorityLabel(value: number): string {
  const label = PROJECT_PRIORITY_LABELS[value];
  if (label !== undefined) return label;
  return value > 0 ? `+${value}` : String(value);
}

/** 편집 드롭다운에 채울 선택지. 큰 값이 위에 오도록 내림차순으로 늘어놓는다. */
export const PROJECT_PRIORITY_OPTIONS: readonly { value: number; label: string }[] = Array.from(
  { length: PROJECT_PRIORITY_MAX - PROJECT_PRIORITY_MIN + 1 },
  (_, i) => {
    const value = PROJECT_PRIORITY_MAX - i;
    return { value, label: projectPriorityLabel(value) };
  },
);
```

`nextSortSelection` 위에 시작 방향 표를 두고, 함수가 그것을 읽게 한다.

```ts
/**
 * 컬럼마다 처음 눌렀을 때의 방향.
 *
 * 적지 않은 컬럼은 오름차순에서 시작한다. **중요도만 내림차순이다** — 중요도로 정렬하는
 * 의도는 거의 언제나 "중요한 것을 위에서 보겠다" 이고, 규칙의 일관성보다 이쪽이 덜
 * 헷갈린다.
 */
const FIRST_ORDER: Partial<Record<ProjectSortField, 'asc' | 'desc'>> = {
  priority: 'desc',
};

export function nextSortSelection(
  current: ProjectSortSelection,
  field: ProjectSortField,
): ProjectSortSelection {
  const first = FIRST_ORDER[field] ?? 'asc';
  if (current?.by !== field) return { by: field, order: first };
  if (current.order === first) return { by: field, order: first === 'asc' ? 'desc' : 'asc' };
  return null;
}
```

> **이름과 달리 훅으로 빼지 않는다.** `useProjectNameEdit` 이 훅인 것은 목록 셀과 상세 화면
> 헤더가 **같은 동작을 공유**하기 때문이다. 설명 편집은 목록에만 있으므로 쓰는 곳이 하나뿐이고,
> 훅으로 빼면 파일만 늘고 읽을 곳이 둘로 나뉜다. 나중에 상세 화면에도 같은 편집이 생기면
> 그때 빼면 된다.

```tsx
import { useState } from 'react';
import type { ProjectListItem } from '@sam/shared';
import { useUpdateProject } from '../lib/projects';
import { apiErrorMessage } from '../lib/errors';
import { toast } from '../lib/toast';

/**
 * 프로젝트 목록의 설명 셀.
 *
 * 보기 모드에서는 한 줄로 자르고, 편집에 들어가면 **그 자리가 여러 줄 입력창으로
 * 늘어난다.** 설명은 최대 2000자라 한 줄짜리 입력창으로는 쓰기 어려운데, 요구의 핵심이
 * "목록 화면을 벗어나지 않는 것" 이라 팝오버 대신 이 방식을 골랐다. 편집하는 동안 행
 * 높이가 커지는 것은 편집 중임을 드러내는 신호로도 읽힌다.
 */
export default function ProjectDescriptionCell({
  project,
  canManage,
}: {
  project: ProjectListItem;
  canManage: boolean;
}) {
  const [editing, setEditing] = useState(false);
  const [draft, setDraft] = useState(project.description ?? '');
  const updateProject = useUpdateProject(project.id);

  const submit = async () => {
    const next = draft.trim();
    const before = project.description ?? '';
    if (next === before) {
      setEditing(false);
      return;
    }
    try {
      await updateProject.mutateAsync({
        // 빈 문자열은 "설명 없음" 이므로 null 로 보낸다.
        description: next === '' ? null : next,
        expectedUpdatedAt: project.updatedAt,
      });
      setEditing(false);
    } catch (err) {
      toast.error(apiErrorMessage(err));
    }
  };

  if (!editing) {
    return (
      <div className="flex min-w-0 items-center gap-1">
        <span className="truncate text-slate-600 dark:text-slate-400" title={project.description ?? ''}>
          {project.description ?? ''}
        </span>
        {canManage && (
          <button
            type="button"
            onClick={() => {
              setDraft(project.description ?? '');
              setEditing(true);
            }}
            title="설명 변경"
            aria-label="설명 변경"
            className="shrink-0 text-slate-400 hover:text-slate-600 dark:hover:text-slate-200"
          >
            ✎
          </button>
        )}
      </div>
    );
  }

  return (
    <textarea
      autoFocus
      rows={3}
      maxLength={2000}
      value={draft}
      disabled={updateProject.isPending}
      onChange={(e) => setDraft(e.target.value)}
      onBlur={submit}
      onKeyDown={(e) => {
        // 여러 줄 입력이므로 Enter 는 줄바꿈이다. 저장은 Ctrl+Enter 로 한다.
        if (e.key === 'Escape') {
          e.preventDefault();
          setEditing(false);
        } else if (e.key === 'Enter' && (e.ctrlKey || e.metaKey)) {
          e.preventDefault();
          void submit();
        }
      }}
      className="w-full rounded border border-slate-300 bg-white px-1.5 py-1 text-sm dark:border-slate-600 dark:bg-slate-800"
    />
  );
}
```

**연필 문자(`✎`)는 `ProjectNameCell` 이 쓰는 아이콘 방식을 먼저 보고 그것과 맞춘다.** 그 파일이 SVG 를 쓰면 같은 SVG 를 쓴다.
